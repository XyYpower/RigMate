# RigMate 视觉母版索引（M27）

> 视觉事实源：`src/ui/theme.css`、`src/app/globals.css`、`src/ui/finding-model.ts`。
> 生成脚本：`scripts/generate-visual-masters.py`（改视觉先改脚本或 SVG，再同步代码）。
> 规则：先确定信息层级，再改图，再改代码；每完成一个页面，用真实浏览器截图验收。

## 主线

**仪器白 / 方案工作台**。

RigMate 的主视觉不再是“八类硬件表单”，而是用户目标、方案结果和需要决策的少量事项。硬件细节和兼容规则按需展开。

## 页面状态索引

| 状态 | 用户看到的重点 | 视觉原则 |
|---|---|---|
| 目标入口 | 我想配置什么 | 大留白、单一输入焦点、少量可选约束 |
| 生成中 | Agent 正在理解/检索/校验 | 短事件、时间戳、静态进度，不做聊天气泡堆叠 |
| 方案就绪 | 这一版方案是什么 | 方案摘要、预算区间、关键硬件和取舍为主视觉 |
| 待确认 | 我只需要做哪些选择 | 每条问题一个动作，隐藏内部字段和规则编号 |
| 已接受 | 方案已进入我的项目 | 版本、更新时间、进入 DIY 和导出动作清晰 |
| 高级 DIY | 我可以精确改哪里 | 保留规格表和规则详情，但作为进阶层 |

## 硬约束

1. 暖白底 `#e8e6df`、面板 `#f7f6f1`、发丝线 `#d6d3c8/#b9b5a7`、墨黑 `#191b19`、仪器橙 `#f4581c`；
2. 语义色只表示系统状态，不作为装饰；
3. 数字、预算、版本、时间使用等宽字体和 tabular-nums；
4. 禁止渐变、发光、玻璃拟态、圆角卡片堆叠、英文 micro-caps 和营销 hero；
5. 方案结果优先于输入字段，内部规则和来源渐进披露；
6. 真实型号、真实目录数据和真实检查结果出图，不使用 Lorem 或虚构证据；
7. 生成中状态使用短事件和克制动效，支持 `prefers-reduced-motion`；
8. 兼容性不使用总分，前台显示结论和动作，详情层保留依据。
