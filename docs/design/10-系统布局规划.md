# RigMate 系统布局规划 v1（UI 总纲）

> **本文档是 UI 的单一事实来源**：先改本文档，再动代码——与"业务规格先行"同一纪律。
> 视觉事实源见 `00-visual-system.md` 与 `boards/`（M21 母版）；本文档管**结构与边界**，不管像素。
> 2026-09-22 制定。背景：用户参考图（豆包 AI 生成）提供骨架思路；现有代码 = 单页工作台。

## 0. 一句话定位

**"先确认能装，再决定买什么"的装机检查工具**。四区导航服务两个用户场景：
自装配机（选件 → 查兼容）与 整机复核（拿到主播/电商配置单 → 查有没有坑）。

## 1. 信息架构：四区导航（采纳自用户参考图）

```
┌───────────────────────────────────────────────────────┐
│  装机配置   硬件中心   方案库   证据台账        🔍 ⚙ 👤  │
└───────────────────────────────────────────────────────┘
```

| 导航区 | 路由 | 状态 | 内容 |
|---|---|---|---|
| **装机配置** | `/` | ✅ 已实现（现单页） | 工作台：项目栏 + 配件录入 + 清单规格表 + 诊断流。核心工作区，保持密度，**不放营销 hero** |
| **硬件中心** | `/hardware` | ⬜ V1-B 早期 | 目录浏览/检索（三层来源标记：种子/人工/BuildCores）、字段完整度、导入审计（catalog_import_runs）、待录清单（检索未命中统计） |
| **方案库** | `/projects` | ⬜ V1-B | 历史项目列表（从下拉升级成页）、**整机复核入口**（粘贴配置单 → 解析 → 检查，承接主播单场景）、报告导出（M21 板 07） |
| **证据台账** | `/evidence` | ⬜ V1-B 中后期 | 价格证据链（追加式快照）、行情关注（M21 F2 板 evidence-ledger / markets-watchlist 的家）。**未启用前导航置灰** |

用户图原第四区"我的配置"：本地单用户工具暂不需要偏好页——数据管理（导入/备份）并入硬件中心；若未来多用户再启用。

## 2. 三步主流程（采纳自用户参考图，与产品闭环一致）

**1 选配件 → 2 检测兼容 → 3 导出方案**

- ①② 已实现（工作台内完成）；
- ③ = V1-B 报告导出（路由 `/builds/[id]/report`，M21 板 07 已画：工程图纸风、七类分节、**不压缩成单一总分**）。

## 3. 尺寸核对画布：复活条件已满足一半

用户参考图中央的"主机 + 热点"视图 = M11/M12 下架的画布。当时下架原因：规格数据稀疏、只剩虚线幽灵件。
现在目录有了真实板长/限长/限高（BuildCores + 人工目录），**复活为工作台内可折叠小部件**（不占中央 C 位）：
有尺寸数据时画透视示意 + 越界标红；无数据的部件仍虚线幽灵。位于清单下方，默认折叠。

## 4. Agent 接入（装机副驾，M21 板 F3 思路延续）

- **形态**：工作台右侧可展开抽屉，**不占导航区**。
- **定位三词**：抽取 / 解释 / 提议。把主播单截图抽成结构化清单、解释某条诊断为什么触发、提议替代型号。
- **红线（业务规格 §3.2/§14 延续）**：
  1. 单助手，不做多 Agent 宣传；
  2. 事实数字只来自规则引擎与目录/快照——LLM 不产出兼容性结论、不填价格；
  3. 抽取结果必须经用户确认才入清单（规格 §8.3 候选确认流）；
  4. 无可靠数据输出"未知"，绝不猜。
- **时序**：最后接。前置依赖 = 报告导出（解释的载体）+ 证据台账（提议的价格依据）。

## 5. 风格

延续 **仪器白 / 技术规格单**（M13-M16 定型，M21 母版固化）。
参考图恰好也是暖白 + 单一橙——方向一致，互为印证。所有新页面复用 `--rm-*` tokens，禁止新起炉灶。

## 6. 迁移路径（不重写，增量拆页）

1. **第一步**：加顶部导航壳（`layout.tsx`），四区可点，未实现区显示"规划中"占位页；工作台原样迁入 `/`。
2. **第二步**：硬件中心 `/hardware`——数据运营视图，纯读 + 已有 API（目录检索/导入审计），无新后端。
3. **第三步**：方案库 `/projects`——项目列表 API 已有（GET /api/builds），补报告导出。
4. **第四步**：证据台账（需 price_evidence 后端，规格 §8.2）。
5. **第五步**：副驾抽屉（agent 接入）。

每步独立可交付，门禁照旧（116+ 单测 / 9+ E2E / 真实浏览器验收）。

## 7. 不做清单（防跑偏）

- ❌ 营销首页 / hero 大标题 / 特性宣传卡（参考图那套是官网语言，不是工具语言）；
- ❌ 3D 渲染 C 位（画布只做核对示意小部件）；
- ❌ 兼容性"评分/总分"（报告红线）；
- ❌ 多 Agent、自动比价、电商爬虫（规格红线不变）；
- ❌ 深色主题回归（M13 用户定向，已否决）。
