# RigMate UI 重构设计基线

日期：2026-09-28
状态：已确认，按参考 UI 图执行

## 1. 重构结论

本次重构以用户提供的两张 RigMate UI 图作为主视觉和交互事实源，不延续当前技术规格单风格。产品统一为明亮、精致、工程感的三栏工作台：左侧固定产品导航，中间是当前任务的主要内容和决策，右侧是 Agent 处理进度、用户需求和兼容性诊断。橙色是唯一主动作色，白色面板、浅灰背景、柔和阴影、轻圆角和清晰分组构成基础视觉。

现有后端 API、数据库、目录、价格证据、兼容规则、方案版本和检查历史全部保留，先重做前端表达，再接着优化 Agent。

## 2. 参考图评价

做得好的地方：工作台结构清楚；橙色主按钮让下一步明确；右侧时间线降低 Agent 黑盒感；配置清单适合快速扫读；橙色、绿色、红色形成一致产品语言。

需要补强的地方：顶部只保留一个主动作；诊断统一为阻断、待补充、通过；配置表固定型号、数量、价格、详情列；空白和错误状态完整设计；移动端把右栏折叠到主内容下方。

## 3. 产品目标

- 用户进入首页可以直接描述目标，看到接近参考图的方案工作台。
- 方案页首屏同时看到方案标题、预算、配置清单、Agent 进度和下一步动作。
- 高级 DIY 保持逐项修改能力，但使用同一套壳、按钮、状态和诊断组件。
- 用户不需要先填写 CPU、主板等八类字段。
- 精确规格、价格和兼容判断都来自现有目录、证据和规则 API。
- 视觉重构完成后，Agent 后端替换不会改变页面结构。

## 4. 统一页面结构

左侧导航固定约 220px，白色背景，显示 RigMate Logo 和副标题。顺序为：开始配置、装机方案、硬件资料、我的方案、高级 DIY、证据台账。当前项使用浅橙背景、橙色图标和右侧短竖线。

顶部工作栏显示当前方案标题、目标摘要、预算、自动检查状态和自然语言修订输入。顶部只允许一个橙色主按钮。

中间主区：首页为自然语言输入、预算快捷设置和示例；方案页为推荐摘要、八类配置清单、决策条和接受/调整/DIY 操作；DIY 页为八类硬件子导航、规格编辑、尺寸预览和保存修改。

右侧上下文栏约 340px。上半部为 Agent 时间线：理解目标、检索候选、自动校验、等待确认。下半部为需求摘要；DIY 页下半部替换为兼容性诊断。每项支持查看依据，展开规则、尺寸、接口、来源或建议。

## 5. 视觉规则

- 页面背景浅灰白，面板纯白，细边框和轻阴影。
- 文字深蓝灰，次级文字保持足够对比度。
- 仪器橙用于主要按钮、当前导航、进度节点和重点价格。
- 成功绿色，警示琥珀色，阻断红色。
- 圆角 8–14px，中文系统无衬线字体，数字使用等宽数字。
- 线性图标保持统一笔画；动效 150–250ms，并支持减少动效。

## 6. 组件清单

创建可复用组件：WorkbenchShell、BrandSidebar、WorkspaceHeader、AgentProgressCard、RequirementCard、CompatibilityPanel、BuildSummaryCard、BuildPartsTable、DecisionBanner、StatusBadge。组件只负责展示和事件回调，API 调用仍放在页面或 application 层。

## 7. 状态、响应式与验收

统一状态为 loading、ready、attention、conflict、unknown、accepted、error。价格、规格、兼容性不由组件推断，不确定信息显示待补充或待确认。

1200px 以上为左 220px、中间自适应、右 340px；900px 以下左栏变为顶部抽屉，右栏排在主内容之后；所有主要按钮保持可见且无横向滚动。

验收要求：首页、方案页、DIY 页共用三栏壳；方案页首屏具备标题、预算、清单、Agent 进度和主动作；诊断可区分三种状态并展开依据；真实 API 流程继续可用；typecheck、lint、单元测试和相关 Playwright 测试通过。

## 8. 实施顺序

共享壳与 token → 首页 → 方案页 → DIY 页 → 项目/资料页 → 响应式与视觉验收 → Agent 后端优化。

这份文档是产品、设计和开发 AI 的共同依据。新增功能必须先说明它属于左栏导航、中间决策区还是右栏上下文区。
