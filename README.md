# RigMate

RigMate 是面向 PC 装机与升级决策的 Agent 工作台。用户可以直接描述目标，例如“2 万预算、白色海景房、剪辑和游戏”，系统自动理解需求、检索硬件资料、生成可编辑方案，并在后台自动校验兼容性和资料缺口。

经验用户可以在同一份方案中进入高级 DIY，逐项替换硬件；普通用户不需要先填写 CPU、主板、显卡等八类字段。确定性规则、目录来源、价格证据和检查历史仍然是系统可信内核，Agent 负责理解目标、组织候选、解释取舍和推进任务。

## 部署边界（内核恢复计划 Task E）

- **RigMate 当前是本地单用户工具**：没有认证、没有多用户项目隔离，所有项目数据共享同一个本地 SQLite 库；
- **Docker 镜像不得直接暴露公网**——容器内服务对局域网任何主机可读写全部数据；公网部署前必须先补认证与项目隔离（见 AI_COLLABORATION §8 后置技术债）；
- 数据库文件（`data/*.db`）与目录导入产物（`data/catalog/`）都是本地数据层，不在 git 内。

## 方案生成的数据事实（内核恢复计划）

- 方案候选只来自通过质量门（`verified` / `supported`）的目录产品；`partial` / `conflicting` / `stale` / `rejected` 一律不进候选空间，缺失类别如实标注；
- 方案价格只认 `review_status=verified` 的价格证据（同地区、绑定 canonical product）；没有已审核价格时上下限为 null、界面显示"暂无已审核价格证据"——不再使用源码常量估价；
- 每个方案项携带 `qualityStatus`、字段质量状态与证据来源引用，可回溯；模型只在质量门过滤后的候选摘要中挑选，非法 ID / 越权字段会被拒绝并回退规则式排序（`npm run evals:design` 可复现评测）。

## 当前状态

已完成的可信内核：

- 八类核心配件、12 条确定性兼容性规则和 `unknown` 诚实降级；
- SQLite 持久化、检查结果、清单指纹和过期标记；
- 标准型号目录、人工目录和 BuildCores 离线导入审计；
- 追加式价格证据台账；
- 方案库、整机复核和报告导出；
- 仪器白 / 技术规格单视觉基础。

产品方向正在从 V1-A 的“逐项录入后检查”迁移到 V2 的“目标驱动方案生成”：

```text
自然语言目标 → 方案草稿 → 自动校验 → 审阅/调整 → 接受后进入 DIY
```

已接入可插拔 LLM 做目标理解：在 `.env` 配置 `RIGMATE_LLM_API_KEY`（任何 OpenAI 兼容端点）即可启用大模型解析预算、用途与偏好；不配置或模型失败时自动降级为本地规则解析。候选、价格与兼容事实始终由目录和规则引擎核验，模型不参与事实判断，界面活动流会如实标注所用模式。旧逐项工作台会保留为 `/diy` 高级入口，不删除已有数据和规则能力。

## 本地启动

```bash
npm install
npm run dev
```

打开 <http://localhost:3000>。数据库表会在服务首次访问时自动创建。

> 全新 clone 里数据库是空的：质量门之后没有候选属正常现象（生成方案会诚实追问）。
> 需要验证完整链路时，用 fixture 基线：`npm run db:fixture -- --fresh` 种入测试目录与
> 已审核价格，或直接跑 `npm run gate:data:fixture` 验证 schema/seed/门禁逻辑。

## 产品边界

RigMate 不自动下单、不做未授权电商抓取、不把模型经验冒充精确事实、不使用兼容性总分，也不以多 Agent 角色作为卖点。精确规格、价格和兼容性必须能回到目录、用户输入、价格证据或确定性规则；模型不可用时，目录候选、高级 DIY 和规则检查仍应可用。
