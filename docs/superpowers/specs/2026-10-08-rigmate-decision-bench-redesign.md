# RigMate 装机决策台视觉重置设计

日期：2026-10-08  
状态：待用户确认  
适用范围：首页、方案审阅页、共用工作台壳与视觉组件

## 1. 背景与问题

当前界面已经具备三栏布局、目标输入、方案清单、Agent 事件和兼容诊断，但整体仍像通用 AI 工作台。用户第一眼看到的是输入框、白色面板和 Agent 时间线，无法立刻理解 RigMate 的核心价值：把目标变成八类硬件配置，并让每个关键选择可以核验。

这次重置不增加模型能力，也不改变现有 API、数据库、目录、证据链、规则引擎、方案版本或接受流程。目标是把“装机”和“核验”提升为主视觉，把“AI”降为实现方案的辅助层。

## 2. 设计定位

RigMate 定位为 **装机决策台**：用户像在一张装配台上组装一套电脑，同时看到预算、兼容关系和资料可信度。

视觉主次固定为：

1. 当前配置和下一步决策；
2. 八类硬件的装配关系；
3. 预算与兼容性结果；
4. 字段证据与来源；
5. Agent 过程说明。

推荐采用“装机工作台为主体、硬件核验为特色”的组合，不采用纯聊天顾问或纯检测仪表盘方向。

## 3. 核心视觉语言

### 3.1 装配轨道

八类部件形成固定顺序的装配轨道：CPU、主板、显卡、内存、存储、电源、散热、机箱。首页为空时显示待填槽位，生成后显示真实型号；方案页显示每一项的型号、价格、质量状态和详情入口。

轨道是 RigMate 的主要识别元素。它替代通用 AI 产品常用的大面积对话框和重复卡片，让用户直接看出产品在“组一台电脑”。

### 3.2 核验标记

每个部件和重要字段都使用统一的证据状态：已核验、可参考、资料不足、待确认、存在冲突。状态必须同时有文字和图形标记，不能只靠颜色。证据入口显示来源、字段和检查时间；没有证据的字段保持待补充。

### 3.3 预算标尺

预算使用横向标尺表达：预算范围、方案估算下限、估算上限、当前余量和超预算区间。标尺是信息组件，不做装饰性渐变；数字仍以人民币和等宽数字显示。

### 3.4 结构色与材质

保留仪器橙作为唯一主动作色，增加石墨黑作为结构线和标题色，铝灰作为画布和槽位底色，蓝灰用于资料和中性上下文。绿色、琥珀、红色只表达真实状态。

不使用渐变文字、玻璃拟态、深色终端、重复的图标卡片网格或装饰性 Agent 头像。面板减少阴影，更多使用发丝线、标尺线、槽位边界和部件线稿建立层次。

## 4. 页面结构

### 4.1 首页：开始组装

首页只保留一个主任务：描述目标并开始组装。

首屏从上到下为：

1. 品牌与极简导航；
2. “开始一套配置”标题和一句产品解释；
3. 八类装配轨道，空槽位显示类别与需要的关键信息；
4. 目标输入、预算输入和开始组装按钮；
5. 预算标尺与“资料核验 / 兼容检查 / 可编辑方案”三个结果承诺；
6. 最近方案和整机复核入口。

示例目标作为输入辅助，不作为主视觉内容。`RigMate 怎么工作` 这类通用说明改为装配轨道下方的简短操作提示。

生成过程中，轨道槽位可显示“正在检索 / 已找到 / 待核验”状态，但不伪造模型步骤或进度百分比。

### 4.2 方案页：审阅并定案

方案页首屏固定显示：方案标题、预算标尺、当前方案状态、配置清单和唯一主动作。

中间主区：

- 方案摘要和用途适配；
- 八类配置清单，固定显示部件、型号、参考价、核验状态和详情；
- 部件详情展开字段证据、来源和对应规则；
- 决策条显示用户必须确认的外观、预算或资料缺口；
- 底部提供接受、继续调整和进入 DIY 的动作，其中同屏只能有一个橙色主按钮。

右侧“核验台”：

- 顶部四阶段轨道：目标、选件、核验、定案；
- 阻断问题优先，其次是资料不足和通过项；
- 每项显示影响、参与部件和可执行动作；
- Agent 事件作为“查看处理记录”折叠内容，不作为主标题。

### 4.3 共用工作台壳

左侧导航收缩为三个主入口：开始配置、我的方案、硬件资料。高级 DIY 和证据台账保留，但从方案或硬件详情进入，避免首页像后台菜单。

顶部工作栏只保留当前方案名、状态、预算摘要和一个全局主动作。自然语言修订输入放在方案内容下方，避免顶部同时出现多个竞争焦点。

DIY、硬件、证据和报告页沿用同一套品牌标记、状态、按钮、表格和来源展开方式，但不强行使用装配轨道替代各页面的专属任务。

## 5. 交互规则

- 用户首先操作目标输入和预算，其次查看装配结果，最后处理核验问题。
- 每个状态都给出下一步动作：查看依据、补充型号、替换部件、进入 DIY 或接受方案。
- 模型失败时，界面保留目标文本和已有结果，显示“已切换到规则式方案”而不是空白或伪造进度。
- 资料不足不得显示为通过；冲突不得被压缩为普通警告。
- 方案页默认展开配置清单，字段证据和规则依据按需展开。
- 移动端顺序固定为目标输入 → 装配轨道 → 配置清单 → 核验台 → 主动作，不产生页面级横向滚动。

## 6. 组件边界

保留并重新定义以下组件：

- `WorkbenchShell`：品牌导航、主区和上下文区的布局边界；
- `AssemblyRail`：八类装配槽位及状态；
- `BudgetRuler`：预算范围、估算区间和余量；
- `BuildPartsTable`：型号、价格、质量状态、详情展开；
- `VerificationDesk`：阻断、缺失、通过和证据入口；
- `DecisionBanner`：用户必须做出的下一步决定；
- `StatusBadge`：统一状态文本、图形和语义颜色；
- `AgentProgressCard`：仅作为可折叠处理记录，不承担页面主叙事；
- `WorkspaceHeader`：当前方案上下文和单一主动作。

展示组件只接收结构化视图数据和事件回调，不在 JSX 或 CSS 中推断质量、价格或兼容结论。

## 7. 响应式要求

- `>= 1200px`：左导航、主区、核验台三栏；装配轨道完整横向展示。
- `900–1199px`：左导航保留，核验台移动到主区下方；轨道允许内部滚动但页面不横向滚动。
- `< 900px`：导航变为顶部菜单，装配轨道变为可横向滚动的内部区域；主动作和核验问题必须在配置清单后立即可达。
- `390px`：长型号使用截断和详情展开，预算标尺保留数字和状态，不依赖悬停显示信息。

## 8. 非目标

本次不做：

- 新增自由聊天主流程；
- 更换数据库、API 或 Agent 编排器；
- 添加实时电商图片、价格爬虫或自动下单；
- 为了视觉效果引入虚构硬件图片或未经核验的规格；
- 一次性重写所有旧页面。

## 9. 验收标准

1. 首次打开首页的用户在 10 秒内能说出产品用途和下一步操作。
2. 首页第一屏能看到目标输入、八类装配轨道和预算关系。
3. 方案页第一屏能看到配置清单、核验状态和唯一主动作。
4. 用户无需阅读 Agent 文案即可完成生成、查看依据、修改或接受方案。
5. partial、unknown、conflicting 状态不会在视觉上伪装成 verified 或 pass。
6. 1440px、1024px、390px 三档下无页面级横向滚动，主动作保持可达。
7. 现有首页、方案、修订、接受、DIY、硬件、证据和报告 API 流程不回退。
8. 完成后通过 `npm run typecheck`、`npm run lint`、`npm test`、相关 Playwright 测试和 `npm run build`。
