## 1. 文档目的

业务规格定义了"系统输出什么"，架构决策定义了"用什么技术实现"。本文回答第三层问题：**用户看到什么、怎么操作、为什么这样设计**。

本文不回答：

- 兼容性规则如何计算、价格快照如何存储（见业务规格）；
- 数据库、LLM 适配器、价格源适配器如何实现（见架构决策）；
- 组件的具体 props 和文件命名（编码阶段决定）。

## 2. 产品远景与前端定位：一个数据核心，三块镜片

产品未来不止是兼容性检查：V1-B 加入价格证据，V1-C 加入价格趋势、提醒、多配置对比；同时项目定位是 Agent 作品——语言理解与解释能力会逐步增强。

这三类能力（结构、时间、语言）在 UI 上不应该做成三个割裂的产品，而是**同一份数据核心（装机项目 + 检查结论 + 价格快照）的三块镜片**：

| 镜片 | 名称 | 用户问题 | 对应数据 |
|---|---|---|---|
| 空间 | **装机台** | "这套能不能装？" | 配件清单 + 兼容性结论 |
| 时间 | **行情台** | "现在买合适吗？最近价格怎么走？" | 价格快照 + 预算 |
| 语言 | **装机副驾** | "帮我把这套整理一下、解释一下" | 以上全部（只读+提议） |

这个结构天然映射"股市那种"体验而不越界：

> **装机清单 = 持仓，价格快照 = 行情，每日日报 = 盘后复盘，过期提醒 = 预警。**

关键红线（来自业务规格 §11、§18）：行情台只做**已发生证据的回放与聚合**，不做涨跌预测、不承诺最低价。图上永远只有历史观察点，不画预测线。

## 3. 设计原则

1. **证据优先美学**。每个数字旁边永远跟着"来源 · 日期 · 证据等级"三件套小字。界面鼓励用户点开证据，而不是只看结论。
2. **未知是一等公民**。`unknown`/待补充/候选待确认不是错误态，是有专属视觉身份的常态（虚线幽灵件、青灰状态灯）。业务规格"缺字段不猜默认值"的哲学必须被看见。
3. **一套语义色贯穿全站**。`pass / block / warn / unknown / not_applicable` 五种结论状态是全站唯一的语义色系，装机台画布、报告、行情新鲜度全部复用，用户学一次就够。
4. **Agent 只提议，人确认**。副驾的所有写操作（确认型号、替换配件）必须经过用户点击；所有结论必须渲染为可追溯的结构化卡片，不接受自由文本充当事实（业务规格 §13）。
5. **LLM 可关闭，产品完整**（架构决策 §1.1）。副驾是增强层。关掉模型后，录入、检查、行情、报告全部可用。
6. **桌面优先，移动可看**（架构决策 §1.1）。装机台/行情台按桌面三栏设计；移动端保留报告阅读、清单查看、行情速览。
7. **性能兜底**。重的渲染层（3D、图表）全部懒加载并保留轻量降级路径（SVG 蓝图 / 纯文本报告）。

## 4. 信息架构与页面地图

```text
全局框架：顶栏（项目切换 · ⌘K 命令/副驾入口 · 检查按钮）+ 右侧副驾抽屉

/                      工作台：项目卡片、每日日报摘要、关注行情速览
/builds/[id]           装机台：清单 + 机器画布 + 诊断流（核心工作区）
/builds/[id]/report    报告页：可导出（浅色图纸风，打印友好）
/markets               行情台：关注列表、快照时间线、配置单估值、每日日报
/evidence              证据台账：全部价格快照与规格来源的审计视图（V1-B）
```

设计要点：

- 工作台是"今天该看什么"的入口：日报摘要、过期证据预警、有阻断的项目置顶。
- 证据台账独立成页，是"可复核"这个卖点的 UI 承诺：任何结论都能跳到这里看原始快照。

## 5. 装机台设计

### 5.1 布局（桌面三栏）

```text
┌────────────────────────────────────────────────────────────────────┐
│ RigMate ▸ 黑曜石-2026Q4      [⌘K 询问副驾]          [检查 ▶] [◨ 副驾] │
├──────────────┬──────────────────────────────────┬──────────────────┤
│ 清单 (8)      │                                  │ 诊断 3阻断·1待补·2警│
│ ● CPU    已确认│         机 器 画 布               │ ┌───────────────┐ │
│ ● 主板    已确认│    （SVG 蓝图 ⇄ 3D 侧透）         │ │! R-PSU-001 阻断│ │
│ ◐ 显卡    候选  │    显卡穿出侧板 → 红              │ │ 结论·证据·日期  │ │
│ ◌ 内存    待补充│    散热器高度标尺 → 黄            │ │ ·置信度·假设   │ │
│ ⋮             │    虚线幽灵件 = 待补充            │ │ ·建议动作      │ │
│ [+ 添加配件]   │  [蓝图|3D] [正|俯|爆炸]           │ │ [▶聚焦部件]     │ │
├──────────────┴──────────────────────────────────┴──────────────────┤
│ 检查历史：#12 今日 14:02（3阻断）· #11 昨日（5阻断）· 本次目录版本 v… │
└────────────────────────────────────────────────────────────────────┘
```

### 5.2 机器画布：兼容性的空间化

核心思想：**业务规格里的 12 条规则大多是物理/空间规则，spec 字段（长度 mm、限高 mm、板型、槽数、瓦数、接口）已经足够画出一台比例正确的机器**。兼容性问题不靠读，靠看见。

| 规则 | 空间化身 |
|---|---|
| 显卡长度 vs 机箱限长 | 卡体穿出玻璃侧板，红光，标注 `336 > 320 FAIL` |
| 散热器高度 vs 限高 | 主板到散热器顶端的标尺，超差段变红 |
| 主板板型 vs 机箱 | 主板在机箱内悬空/顶不到螺丝柱位 |
| 内存代际/条数 | 内存条半浮出插槽变色；超槽数的条数无位可插 |
| 供电接口/功耗 | PSU→部件线缆断开闪烁；电流粗细=瓦数，余量表 |
| 待补充字段 | 部件显示为虚线幽灵，点击列出缺失字段 |

实现分两步（详见 §10）：先用 SVG 侧视蓝图验证交互，布局引擎（由 spec 计算部件位置尺寸）与将来 3D 共用；3D 用 React Three Fiber 升级渲染层，`dynamic import` 关闭 SSR，feature flag 控制，SVG 永远是降级路径。

### 5.3 诊断流与六要素卡片

右栏按业务规格 §9.4 排序：阻断 → 待补充（未知）→ 警告 → 通过。每张卡片固定渲染规格 §12.3 的六要素：结论、证据、数据日期、置信度、假设条件、建议动作。卡片与画布双向联动：点卡片聚焦部件，点部件反查规则。

### 5.4 检查仪式与点亮时刻

- 发起检查：POST 自检序列动画（CPU INIT → DRAM → VGA → …），有问题的步骤亮对应 Debug 灯并停住——检查过程本身成为过渡动画。
- 全部通过：**点亮仪式**——风扇转起、RGB 波纹扫过整机、一声 POST 音。这是产品的情绪峰值，成本极低。
- 修改配件后：受影响的旧结论按规格 §6.6 标记"过期"，检查历史可对比，不原地改写。

### 5.5 换件推演（升级场景，V1-C）

拖一块新显卡悬停在旧件上方：新旧两套判定实时并排重算，旧件半透明、新件实体化，受影响规则重新走线，功耗余量条重新充满/溢出，确认才落位。把"升级前纠结"变成高光交互，纯前端可实现。

## 6. 行情台设计

### 6.1 关注列表（watchlist）

每行：型号 · 最新观察价 · 较前值变化（7 天）· **新鲜度灯**（●较新 / ◐近期参考 / ○较旧 / ✕过期，颜色复用语义色系）· 证据条数。过期证据灰显但仍可查看——历史是资产，只是不参与当前判断（规格 §11.4）。

### 6.2 快照时间线（单品详情）

- **散点层**：每条快照一个点，纵轴价格、横轴采集时间；颜色=渠道/商品状态（自营、第三方、散片、二手分色——可比性规则的可视化），透明度=新鲜度。
- **日聚合层**：可切换为"类 K 线"竖条（开=当日首条，收=当日末条，高低=极值）。仅聚合**可比样本**；口径混杂时明示"样本不可比"并只显示散点。
- 样本不足时固定显示规格 §11.5 的话术："暂无足够证据进行当前价格判断……"，不画图硬凑。

图表库选 TradingView 开源的 Lightweight Charts（Apache-2.0，体积极小，时间线/金融图专用）；简单统计图用自绘 SVG 以保持蓝图风格一致。

### 6.3 配置单估值曲线（"持仓"视图）

杀手级功能：**"我的配置单今天值多少钱"**。快照追加不可覆盖 ⇒ 可以重放任意历史日期，计算整份清单的已计价总额随时间的曲线。展示：

- 已计价金额曲线 + 预算水平线；
- 未计价件数与"未知区间"阴影带（未知件不按零元计，规格 §10.1）；
- 悬停任一天，显示当日每件的证据快照——曲线每一点都可审计。

这是"股市感"的诚实版本：不预测，只回放。同时天然支撑"内存最近在涨，要不要早买"这类真实决策场景（规格 §4.2 场景 4）。

### 6.4 每日日报

结构固定，数字由代码从快照计算，LLM 只写叙述且可关闭：

1. 今日新增证据（条数、来源分布）；
2. 显著波动（关注列表中变化超过阈值的型号，附样本量与口径说明）；
3. 证据到期预警（哪些关注项的新鲜度即将跌出可判断区间）；
4. 预算影响（有项目引用的型号价格变动 → 对配置单估值的影响）；
5. 结论置信度声明（"以下判断基于 N 条可比证据，截至 X 日"）。

V1-B 阶段日报由用户在行情台触发生成；定时自动生成/推送推后到 V1-C（避免提前引入任务调度基础设施，架构决策 §10）。

### 6.5 提醒（V1-C）

两类：价格新鲜度过期提醒（关注项证据全部过期）、显著波动提醒。提醒内容一律链接回证据，不推裸数字。

## 7. 装机副驾设计（Agent 交互层）

### 7.1 形态

- 全局右侧抽屉（桌面）+ ⌘K 命令面板。命令面板同时是"人类快捷操作"和"询问副驾"两个入口。
- 副驾不另做一套界面：**它驱动的是人用的同一套 UI**。这是建立信任的关键——agent 说"显卡超长"，画布真的聚焦过去。

### 7.2 事件协议（前端契约）

副驾输出不是自由文本，而是 Zod 定义的类型化事件流（SSE，Next Route Handler 推送）：

| 事件 | 渲染为 | 是否需要确认 |
|---|---|---|
| `parse_result` | 输入解析卡（识别类别/字段/置信度） | 否 |
| `match_candidates` | 候选对比卡（差异高亮，规格 §6.3） | **是**（确认型号） |
| `finding` | 六要素诊断卡（同诊断流样式） | 否 |
| `price_digest` | 价格证据卡（区间/样本/日期） | 否 |
| `view_intent` | 视图指令：聚焦部件/高亮/打开过滤/切换视图 | 否（只读视图操作） |
| `proposal` | 变更提议卡（替换件/补充字段）+ [接受][忽略] | **是** |
| `error` | 降级说明卡（说明为什么无法判断） | 否 |

关键约束：

- `view_intent` 只能操作只读视图状态，永远不能直接改数据；
- 一切写操作走 `proposal` → 人点击确认，与规格 §6.3 的型号确认机制同构；
- 每张卡片必须能展开看"它为什么这么说"（引用的规则编号/证据 ID）；
- LLM 适配器关闭或超时：副驾入口显示降级态，其余功能不受影响（架构决策 §5.4）。

### 7.3 副驾的职责边界（照抄业务规格 §13 并翻译成 UI 语言）

模型可以：抽字段、解释结论、写日报叙述、生成待补充清单。模型不能：最终定型号、判兼容、报价格真伪——这些卡片上的数字永远来自规则引擎和快照库，卡片上注明"由规则 R-XXX-001 计算"而非"AI 认为"。

## 8. 视觉语言

### 8.1 气质

**深色硬件终端 + 工程蓝图**：近黑底（OLED 友好，装机佬审美）、细描线、等宽数字；点缀受控的 RGB 光效（仅用于点亮仪式与状态强调，不做日常噪音）。报告导出场景用浅色"图纸"风（白底描线 + 图框标题栏），打印友好。

### 8.2 语义色系统（全站唯一语义色）

| 状态 | 色 | 视觉身份 |
|---|---|---|
| pass | 绿 | 实线、稳态 |
| block | 红 | 实线加粗、闪烁/泛光 |
| warn | 琥珀 | 实线、脉动 |
| unknown/待补充 | 青灰 | **虚线幽灵**（部件、卡片、图表通用） |
| not_applicable | 极淡灰 | 降透明度、无动效 |

匹配状态（已确认/候选/未知，规格 §8.3）复用同色系做清单状态点，避免颜色爆炸。

### 8.3 排版与数据

- 正文用系统中文字体栈；**所有数字用等宽/表格数字**（`font-variant-numeric: tabular-nums`），价格列不跳动。
- 证据三件套（来源 · 日期 · 等级）是固定的小字组件 `<EvidenceStamp>`，出现在每一个数字旁。
- Tailwind 4 `@theme` 定义 tokens（色板、间距、状态色、动效时长），shadcn/Radix 组件统一吃 tokens。

### 8.4 动效

克制：状态变化用数字滚动与颜色过渡；检查用 POST 序列；通过用点亮仪式；其余场景默认无动效，并尊重 `prefers-reduced-motion`。

## 9. 前端技术选型（对齐 ADR，新增部分及理由）

| 关注点 | 选型 | 说明 |
|---|---|---|
| 组件库 | shadcn/ui + Radix + lucide-react | ADR 已定 |
| 样式 | Tailwind 4 + `@theme` tokens | 已在用 |
| 行情图表 | Lightweight Charts | Apache-2.0，小体积，K线/时间线专用 |
| 简单图表 | 自绘 SVG | 保持蓝图描线风格统一 |
| 3D 画布 | React Three Fiber v9 + drei | 支持 React 19；`next/dynamic` 关 SSR；feature flag |
| 动效 | Framer Motion（motion） | 仅用于检查仪式/点亮/卡片联动 |
| 副驾事件流 | SSE + Zod contracts（`src/contracts`） | 与 ADR 的可插拔 LLM 适配器对接 |
| 状态 | React Server Components 优先；交互态本地 useState；跨页缓存引入 TanStack Query 于 F2 评估 | 不提前引入全局状态库 |

依赖纪律：每阶段新增依赖不超过一张表；3D 与图表均为懒加载，首屏不付出代价。

工程提醒（来自 AGENTS.md）：Next.js 16 相对既往版本有破坏性变更，编码前先读 `node_modules/next/dist/docs/` 对应章节。

## 10. 分阶段落地（与业务 V1-A/B/C 对齐）

### F1 · 随 V1-A（当前）：把"检查"做成产品脸面

- 设计 tokens + 语义色系统 + `EvidenceStamp`/六要素诊断卡组件；
- 装机台三栏布局 + 报告页改造；
- SVG 蓝图画布 v0（布局引擎由 spec 驱动）+ POST 检查动画 + 点亮仪式（SVG 版）；
- 纯文本报告视图（降级/无障碍/测试锚点）。

零重量级新依赖。此阶段的布局引擎与坐标计算在 F3 的 3D 升级中原样复用。

### F2 · 随 V1-B：行情台

- 手动/用户提交快照的录入流 UI（带证据三件套）；
- 关注列表 + 单品快照时间线 + 证据台账页；
- 配置单估值曲线 v1；
- 每日日报 v0（用户触发，代码算数字、模板文案）。

### F3 · V1-C 早期：3D 与副驾

- R3F 3D 侧透画布（复用 F1 布局引擎，feature flag，SVG 兜底）；
- LLM 适配器启用：输入解析 + 候选对比 + 结论解释；副驾抽屉 v1（事件协议、proposal 确认流、view_intent 联动）；
- 价格新鲜度/波动提醒。

### F4 · V1-C 中后期

- 换件推演（升级模式）、多套配置对比视图；
- 日报定时生成与订阅推送（届时再评估是否需要任务调度设施）；
- 移动端阅读型布局完善。

## 11. 边界与红线（从业务规格直接继承）

1. 行情台只做已发生证据的回放与聚合；不画预测线，不输出"现在不买一定涨价"类结论。
2. 未知金额不按零元计入估值曲线；样本不可比时拒绝画聚合图。
3. 副驾卡片上的事实数字只能来自规则引擎与快照库；模型文案必须带"解释"标识且可关闭。
4. LLM 关闭时全功能可用（除副驾对话本身）。
5. 不为视觉效果引入 V1 禁止的基础设施（Redis、队列、向量库等，架构决策 §10）。
6. 点亮仪式等动效必须可通过 `prefers-reduced-motion` 关闭。

## 12. 未决问题

1. 深色是否为唯一默认（浅色仅用于导出报告），还是提供双主题？
2. 机器画布的默认视角（正视/爆炸）与机箱朝向，是否按 ITX/ATX 分模板？
3. 行情台关注的冷启动：没有关注列表时展示什么（品类热度需要目录数据支持，V1-B 数据量可能不足）？
4. 副驾抽屉在首次使用时是否需要一段"它能做什么/不能做什么"的能力声明？
5. 配置单估值曲线的时间粒度（日/周）与快照稀疏时的插值策略——倾向不插值，显示断线。

### 13.3 副驾（Agent UI）层——F3 决策输入

| 选项 | 结论 |
|---|---|
| [assistant-ui](https://www.assistant-ui.com)（~7.9k★，MIT） | 首选外壳：headless、可组合聊天原语，Tailwind 友好，自定义成本低 |
| [Vercel AI SDK + AI Elements](https://ai-sdk.dev) | 运行层：SSE 流式 + generative UI，与本设计的类型化事件协议天然对齐 |
| [CopilotKit](https://copilotkit.ai)（~28.6k★） | 暂不引入：整套 agent runtime 与自有协议绑定过深，超出 ADR §5.4 的克制边界 |

副驾的七事件协议是自有的（`src/contracts` 的 Zod schema），聊天外壳用 assistant-ui 原语 + 自渲染事件卡即可，不引入整套框架。
